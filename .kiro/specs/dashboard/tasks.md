# Implementation Plan

- [x] 1. ロールベースルーティングとページ基盤の構築
- [x] 1.1 ダッシュボードページをServer Componentに書き換え、認証チェックとロール判定を実装する
  - 既存のプレースホルダーページを置き換え、`createClient()` で認証情報を取得する
  - `profiles` テーブルからロール (`role`) を取得し、Manager は `/users`、Super Admin は `/admin/grading` にリダイレクトする
  - User ロールの場合のみダッシュボードコンテンツを表示する骨格を用意する
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 1.2 アカウント無効化バナーを実装する
  - Admin Client を使用してログインユーザー自身の `banned_until` を取得し、無効化状態を判定する
  - 無効化されている場合、画面上部に警告バナーを表示する（テキスト: 「アカウントが無効化されています。詳細は管理者にお問い合わせください。」）
  - 無効化状態でもダッシュボードの各セクションは通常通りデータを表示する
  - _Requirements: 7.1, 7.2_

- [x] 2. ダッシュボードデータ取得基盤の構築
- [x] 2.1 全ダッシュボードデータの並列取得ロジックを実装する
  - `profiles` から `default_genre`, `full_name` 等の追加フィールドを1回のクエリで取得する
  - `Promise.all` で独立した10種のクエリ（月次目標、週次目標、当月日報、教材セクション一覧、チュートリアル一覧、完了済みセクション、コーチングクレジット、コーチングセッション、模擬案件、スキルレポート）を並列実行する
  - 各クエリでは必要最小限のカラムのみ選択し、適切な WHERE 条件・LIMIT を設定する
  - `getActiveVersionId()` を使ってアクティブなコンテンツバージョンを解決し、教材クエリに適用する
  - 個別クエリのエラーは該当セクションのみに影響させ、他セクションは正常表示を維持するグレースフルデグラデーションを実現する
  - _Requirements: 1.4, 2.1, 2.2, 3.2, 4.1, 5.1, 5.2, 6.1, 6.2_

- [x] 2.2 取得データを各カードコンポーネントの Props 型に整形するロジックを実装する
  - 月次・週次の目標達成率を算出する（実績時間合計 / 目標時間、目標未設定時は null）
  - チュートリアルごとの教材完了率を算出する（完了セクション数 / 全セクション数）
  - 当日の日報入力状況を判定する（入力済み: 学習時間・内容のサマリー、未入力: フラグのみ）
  - 模擬案件のステータスを `deriveProjectStatus()` で導出し、進行中と直近完了（最新3件）に分類する
  - スキルレポートのカテゴリ別達成率を集計する（`category_large` ごとの `is_ok` 割合）
  - _Requirements: 2.1, 2.2, 3.2, 4.1, 6.1, 6.2, 6.3_

- [x] 3. 学習進捗セクションのカードコンポーネント群を実装する
- [x] 3.1 (P) 目標達成率カードを実装する
  - 今月の学習目標達成率（実績時間 / 目標時間）をプログレスバーとパーセンテージで表示する
  - 今週の学習目標達成率を同様にプログレスバーとパーセンテージで表示する
  - 達成率 100% 超の場合、プログレスバーは 100% でキャップし、テキストは実値を表示する
  - 月次目標が未設定の場合は「目標未設定」と表示し `/daily-reports` への設定リンクを提示する
  - 週次目標が未設定の場合も同様に「目標未設定」と設定リンクを表示する
  - shadcn/ui の Progress コンポーネントを使用する（未導入の場合は追加する）
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [x] 3.2 (P) 教材完了率カードを実装する
  - ユーザーの `default_genre` に対応するチュートリアル一覧を表示し、各チュートリアルの完了率をプログレスバーで表示する
  - 各チュートリアルの完了率をパーセンテージテキストとセクション数（例: "12 / 15 セクション (80%)"）で併記する
  - チュートリアル名をクリックすると `/contents/{tutorialSlug}` に遷移するリンクを設定する
  - 該当ジャンルに教材が存在しない場合は「教材なし」と表示する
  - `default_genre` が null の場合は「ジャンルが設定されていません」と表示する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [x] 4. 日報・コーチング・模擬案件セクションのカードコンポーネント群を実装する
- [x] 4.1 (P) 今日の日報カードを実装する
  - 今日の日報が入力済みの場合、本日の学習時間合計と内容のサマリーを表示する
  - 今日の日報が未入力の場合、「今日の日報を入力しましょう」のCTAボタンを表示する
  - 日報セクション内のリンクをクリックすると `/daily-reports` ページに遷移する
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [x] 4.2 (P) コーチング情報カードを実装する
  - コーチングクレジットの残高（`coaching_credits` の `amount` 合計）を表示する
  - 次回予約済みセッションが存在する場合、日付・時間・ジャンルを表示する
  - 予約済みセッションが存在しない場合、「予約なし」と表示し `/coaching` へのリンクを提示する
  - コーチングセクションのリンクをクリックすると `/coaching` ページに遷移する
  - _Requirements: 5.1, 5.2, 5.3, 5.4_

- [x] 4.3 (P) 模擬案件ステータスカードを実装する
  - 進行中の模擬案件（着手済みかつ未完了）の一覧を表示する
  - 直近の完了済み案件（最新3件まで）を表示する
  - 各案件のタイトルとステータス（着手中/提出済み/採点中/採点完了/差し戻し）を Badge コンポーネントで色分け表示する
  - 案件名をクリックすると `/projects/{slug}` に遷移するリンクを設定する
  - 進行中の案件が存在しない場合、「進行中の案件なし」と表示し `/projects` へのリンクを提示する
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_

- [x] 5. スキルレポートカードを実装する
  - Client Component（`"use client"`）として実装し、`@nivo/radar` の `ResponsiveRadar` でレーダーチャートを描画する
  - カテゴリ別（`category_large`）の達成率をチャートで視覚化し、チャート下部にテキストで併記する
  - 採点済みの案件がない場合（`hasData` が false）、「採点済みの案件がありません」と表示する
  - タスク3・4のカードとは異なり Client Component が必須のため並列実装不可（Task 2 のデータ整形完了が前提）
  - _Requirements: 1.4_

- [x] 6. ページ統合とレイアウト調整
- [x] 6.1 全カードコンポーネントをダッシュボードページに統合し、レスポンシブレイアウトを構築する
  - バナー -> 目標達成率・教材完了率 -> 日報・コーチング -> 模擬案件・スキルレポートの順でセクションを配置する
  - 全セクションが閲覧専用であること（データの作成・更新操作がないこと）を確認する
  - グリッドレイアウトでレスポンシブ対応する（モバイル: 1カラム、デスクトップ: 2カラム）
  - _Requirements: 1.1, 1.4_

- [x] 6.2 エラーバウンダリとエッジケースの検証を行う
  - 全クエリ失敗時に `error.tsx` でエラーバウンダリが表示されることを確認する
  - 個別クエリエラー時に該当セクションのみ「データを取得できませんでした」と表示されることを確認する
  - アクティブバージョンが存在しない場合に教材セクションが「教材が公開されていません」と表示されることを確認する
  - 各セクションの空データ状態（目標未設定、教材なし、日報未入力、予約なし、案件なし、採点なし）のフォールバック表示を通しで検証する
  - _Requirements: 2.4, 2.5, 3.5, 4.3, 5.3, 6.5_

- [x]* 7. 受け入れ基準に基づくテストカバレッジの整備
- [x]* 7.1 (P) 目標達成率の計算ロジックのユニットテストを作成する
  - パーセンテージ算出（正常値、100%超、0除算、null ハンドリング）を網羅する
  - _Requirements: 2.1, 2.2, 2.3_

- [x]* 7.2 (P) 教材完了率の計算ロジックのユニットテストを作成する
  - 完了セクション / 全セクションの算出（正常値、全完了、0セクション）を網羅する
  - _Requirements: 3.1, 3.2_

- [x]* 7.3 (P) ロールベースリダイレクトのインテグレーションテストを作成する
  - Manager アクセス時に `/users` へリダイレクトされることを検証する
  - Super Admin アクセス時に `/admin/grading` へリダイレクトされることを検証する
  - User アクセス時にダッシュボードが表示されることを検証する
  - _Requirements: 1.1, 1.2, 1.3_

- [x]* 7.4 (P) 各カードコンポーネントのレンダリングテストを作成する
  - 各カードが正常データ・空データ・エラー状態の各パターンで期待通りに表示されることを検証する
  - リンク先（`/daily-reports`, `/coaching`, `/projects`, `/contents/{tutorial}`）が正しく設定されていることを検証する
  - _Requirements: 4.2, 4.3, 4.4, 5.2, 5.3, 5.4, 6.3, 6.4, 6.5_
