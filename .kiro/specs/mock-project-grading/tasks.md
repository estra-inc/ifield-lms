# Implementation Plan

## Task Overview

模擬案件の採点・スキルレポート機能の実装タスク。チャートライブラリは Nivo (@nivo/radar)、採点データ保存は新規テーブル分離（B案: `project_evaluations` + `project_evaluation_details`）で確定。

---

- [x] 1. 型定義とスコア計算ユーティリティの実装
- [x] 1.1 PRD 準拠の階層型評価項目の型定義を追加する
  - `EvaluationCategory`（`category_large`, `category_medium`, `items`）と `EvaluationItemEntry`（`id`, `label`, `point`）の型を定義する
  - 既存の `EvaluationItem` 型を非推奨とし、新しい階層型に置き換える方針を整理する
  - `EvaluationState`（チェック状態の Record 型）、`CategoryScore`（大項目別スコア）の型を定義する
  - `GradingResultData`（確定時に `result_data` に保存する構造）の型を定義する
  - `project_submissions` の型に `feedback_comment` フィールドを追加する
  - _Requirements: 2.1, 3.3, 5.3_

- [x] 1.2 (P) スコア計算ユーティリティを実装する
  - 階層型チェックリストの評価結果からスコアを計算するユーティリティ関数を作成する
  - 計算式: `(OK 判定された項目の point 合計 / 全項目の point 合計) x 100`（小数点以下四捨五入）
  - 大項目（`category_large`）ごとの小計（OK 数、全項目数、取得ポイント、全ポイント、達成率%）を算出する
  - 全項目が未評価の場合はスコア 0% を返す
  - フロントエンドとサーバーサイドの両方で使用する共有モジュールとして配置する
  - _Requirements: 3.1, 3.4, 3.5_

- [x] 1.3 (P) スコア計算ユーティリティのユニットテストを実装する
  - 全項目 OK、全項目 NG、混在パターン、空入力でのスコア計算を検証する
  - 大項目別スコアの集計結果を検証する
  - ポイントが異なる項目が混在する場合の重み付き計算を検証する
  - _Requirements: 3.1, 3.4, 3.5_

- [x] 2. データベーススキーマ変更と RPC 関数の実装
- [x] 2.1 `project_submissions` テーブルへの `feedback_comment` カラム追加マイグレーションを作成する
  - `feedback_comment TEXT` カラムを既存テーブルに追加する
  - 既存データへの影響がないことを確認する（NULL 許容）
  - _Requirements: 5.3_

- [x] 2.2 採点データ保存用の新規テーブルを作成する
  - `project_evaluations` テーブル（`submission_id` UNIQUE, `grader_id`, `status`, `score`, `feedback_comment`）を作成する
  - `project_evaluation_details` テーブル（`evaluation_id`, `item_id`, `category_large`, `category_medium`, `item_label`, `point`, `is_ok`）を作成する
  - 必要なインデックス（`category_large` 集計用、`evaluation_id` + `item_id` ユニーク制約等）を作成する
  - _Requirements: 3.3, 6.4_

- [x] 2.3 RLS ポリシーを設定する
  - `project_evaluations`: 受講生は自身の `finalized` 評価のみ参照可能とするポリシーを作成する
  - `project_evaluations`: Manager は全ユーザーの `finalized` 評価を参照可能とするポリシーを作成する
  - `project_evaluation_details`: 受講生は自身の評価詳細のみ参照可能とするポリシーを作成する
  - `project_evaluation_details`: Manager からのアクセスは不可（ポリシーなし）とする
  - 採点操作は `service_role` 経由で RLS をバイパスする設計のため、書き込みポリシーは不要
  - _Requirements: 12.1, 12.2, 12.3, 12.4, 12.7_

- [x] 2.4 採点確定用の RPC 関数を作成する
  - `finalize_grading` PostgreSQL 関数を作成し、単一トランザクション内で以下を実行する: 評価データの確定更新、`project_submissions` のステータスを `graded` に更新、スコアと `feedback_comment` の保存、排他制御の解除
  - ステータス遷移の検証を行い、`grading` 以外からの遷移は EXCEPTION で拒否する
  - 存在しない `submission_id` に対しても EXCEPTION を raise する
  - `graded` 済みの submission への変更試行も拒否する
  - _Requirements: 4.1, 4.3, 4.5, 13.1, 13.2, 13.4_

- [x] 2.5 新規テーブルの型定義を追加する
  - `project_evaluations` と `project_evaluation_details` の Row / Insert / Update 型を TypeScript 型定義に追加する
  - Relationships（FK 定義）も型に反映する
  - 2.2 のテーブル作成後に実施する
  - _Requirements: 3.3, 6.4_

- [x] 3. 未採点提出一覧ページの実装
- [x] 3.1 未採点一覧の Server Component ページを実装する
  - `status` が `submitted` または `grading` の全提出物を提出日時の昇順で取得・表示する
  - 各提出物に受講生名、案件タイトル、GitHub URL、提出日時、ステータスバッジを表示する
  - `submitted` と `grading` をバッジで視覚的に区別する（`grading` は「採点中（下書き）」バッジ）
  - 提出物クリックで採点画面へ遷移するリンクを設ける
  - 未採点提出物が存在しない場合は「未採点の提出はありません」の空状態メッセージを表示する
  - Super Admin ロール限定のアクセスチェックを行う
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 3.2 (P) ジャンルフィルタ機能を実装する
  - `searchParams` を利用した `engineering` / `design` のジャンルフィルタ UI を実装する
  - フィルタ選択時に URL パラメータを更新し、Server Component でフィルタ適用した結果を表示する
  - 全ジャンル表示のデフォルト状態も提供する
  - _Requirements: 1.6_

- [x] 4. 採点画面（チェックリストフォーム）の実装
- [x] 4.1 採点画面の Server Component ページを実装する
  - URL パラメータから `submissionId` を取得し、提出物・案件・評価項目データを取得する
  - 受講生名、案件タイトル、提出 GitHub URL（新しいタブで開くリンク）を表示する
  - ページアクセス時に `submission.status` を `grading` に更新する
  - 既に他の採点者が `grading` に変更済みの場合、警告を表示し続行するか確認する
  - 既存の下書きデータが存在する場合、復元データを取得して ChecklistForm に渡す
  - Super Admin ロール限定のアクセスチェックを行う
  - _Requirements: 2.1, 2.3, 2.4, 2.7, 2.8_

- [x] 4.2 階層型チェックリストの Client Component を実装する
  - 大項目 > 中項目 > 小項目の階層構造をアコーディオン形式で表示する
  - 各小項目に OK/NG のチェックボックストグルを提供する
  - 大項目ごとの小計（OK 数 / 全項目数）をリアルタイムで表示する
  - 全体スコア（%）をリアルタイムで計算・表示する（タスク 1.2 のスコア計算ユーティリティを使用）
  - フィードバックコメント入力欄（テキストエリア、最大 2000 文字制限）を設ける
  - 下書きデータが渡された場合、チェック状態とフィードバックコメントを初期値として復元する
  - _Requirements: 2.1, 2.2, 2.5, 2.6, 3.1, 3.4, 3.5, 5.1, 5.2, 5.5, 6.2_

- [x] 4.3 下書き保存の Server Action を実装する
  - 「一時保存」ボタン押下時に現在のチェック状態とフィードバックコメントを保存する
  - `submission.status` は `grading` のまま維持する
  - `createAdminClient()` を使用して RLS をバイパスする
  - Super Admin ロール限定のチェックを行う
  - 保存完了時にトースト通知を表示する
  - _Requirements: 6.1, 6.3, 6.4_

- [x] 4.4 採点確定の Server Action を実装する
  - 「採点確定」ボタン押下時に確認ダイアログを表示し、確定操作が取り消し不可であることを警告する
  - 全項目未評価の場合はエラーメッセージを表示し確定を受け付けない
  - サーバーサイドでスコアを再計算し、フロント側プレビューとの整合性を検証する
  - `finalize_grading` RPC を呼び出して、評価データ・ステータス・スコア・フィードバックコメントを同一トランザクションで保存する
  - 確定完了時にトースト通知とスキルレポートへのリンクを表示する
  - `revalidatePath` で関連ページのキャッシュを更新する
  - _Requirements: 3.2, 3.3, 3.5, 4.1, 4.2, 4.3, 4.4, 5.3, 13.1, 13.2, 13.3_

- [x] 5. 受講生向け採点結果閲覧の実装
- [x] 5.1 (P) 採点結果詳細表示コンポーネントを実装する
  - `graded` 済みの提出物に対してスコア（%）とフィードバックコメントを表示する
  - 大項目 > 中項目 > 小項目のアコーディオン形式で各項目の OK/NG をアイコンで区別して表示する
  - 大項目ごとの小計（OK 数 / 全項目数、達成率%）を表示する
  - `submitted` または `grading` 状態の提出物に対しては、採点結果セクションを非表示にし「採点待ち」または「採点中」メッセージを表示する
  - 受講生は閲覧のみ可能（変更操作を提供しない）
  - タスク 4 の採点画面とは独立しており、型定義（タスク 1）のみに依存する
  - _Requirements: 7.1, 7.2, 7.3, 7.4, 7.5_

- [x] 6. スキルレポート画面の実装
- [x] 6.1 Nivo (@nivo/radar) によるレーダーチャートコンポーネントを実装する
  - `@nivo/radar` と `@nivo/core` をインストールし、`ResponsiveRadar` コンポーネントでレーダーチャートを描画する
  - 各軸の値を達成率（0-100%）で表示し、頂点に軸名と達成率の数値を表示する
  - 表示対象データが 1 軸以下の場合はプログレスバー形式にフォールバックする
  - レスポンシブ対応とし、モバイル画面でも視認可能なサイズで描画する
  - `"use client"` コンポーネントとして実装する
  - `gridLabelOffset` でラベル位置を調整し、小サイズ（300x300px）でもラベル切れを防止する
  - _Requirements: 9.1, 9.2, 9.3, 9.4, 9.5_

- [x] 6.2 受講生向けスキルレポートページを実装する
  - 認証済みユーザーの `graded` 済み全案件のスコアを集約し、案件ごとにレーダーチャートで表示する
  - `category_large` を軸として自動導出し、案件ごとの達成率を算出する
  - 同一案件に複数回の採点がある場合、最新の `graded` 結果を集計対象とする
  - レーダーチャートの下に案件ごとの詳細セクション（案件名、スコア、採点日）をリスト表示する
  - 詳細セクションの案件クリックで採点結果詳細（タスク 5.1）へ遷移する
  - 採点完了済みの案件が存在しない場合は空状態メッセージを表示しレーダーチャートを非表示にする
  - _Requirements: 8.1, 8.2, 8.3, 8.4, 8.5_

- [x] 6.3 (P) Manager 向けスキルレポート閲覧ページを実装する
  - Manager がユーザー詳細画面からスキルレポートリンクをクリックして当該受講生のスキルレポートを閲覧できるようにする
  - Manager に対してはスキルレポートの閲覧のみを許可し、採点操作は提供しない
  - Manager は `evaluation_items` 詳細（項目レベルの OK/NG）にはアクセスできず、スコアと達成率の集約結果のみ表示する
  - 採点完了済みの案件が存在しない場合は空状態メッセージを表示する
  - 受講生向けスキルレポート（タスク 6.2）と RadarChart コンポーネント（タスク 6.1）を共有し、表示内容をロールで分岐する
  - _Requirements: 10.1, 10.2, 10.3, 10.4_

- [x] 6.4 (P) Super Admin 向けスキルレポート閲覧を実装する
  - Super Admin がユーザー詳細画面からスキルレポートリンクをクリックして任意の受講生のスキルレポートを閲覧できるようにする
  - Super Admin に対しては `evaluation_items` の項目レベルの採点詳細（OK/NG 結果）も閲覧可能とする
  - 採点完了後にスキルレポート画面へのリンクを表示する（タスク 4.4 の確定完了トーストと連動）
  - Manager 向けページ（タスク 6.3）と同じルートでロール分岐する
  - _Requirements: 11.1, 11.2, 11.3_

- [x] 7. アクセス制御とステータス遷移の統合検証
- [x] 7.1 権限制御の統合を実装・検証する
  - 採点画面への Middleware レベルのアクセス制御（Super Admin 限定）を確認する
  - 権限のないユーザーが採点画面 URL に直接アクセスした場合の 403 エラーまたはダッシュボードリダイレクトを実装する
  - 受講生が採点操作（ステータス変更、スコア保存）を実行できないことを RLS レベルで確認する
  - 受講期間終了後（`graduation_date` 超過）の受講生がスキルレポートを閲覧可能であることを確認する
  - _Requirements: 12.1, 12.2, 12.5, 12.6_

- [x] 7.2 ステータス遷移の整合性を検証する
  - `submitted` -> `grading` -> `graded` の正常遷移フローが動作することを確認する
  - `graded` 済みの submission に対するステータス変更が拒否されることを確認する
  - 不正な遷移リクエスト（`submitted` -> `graded` 直接遷移等）がサーバーサイドで検証・拒否されることを確認する
  - 排他制御の解除（採点確定後に次案件の着手が可能になること）が正しく動作することを確認する
  - _Requirements: 13.1, 13.2, 13.3, 13.4_

- [x] 8. 全体結合と動作確認
- [x] 8.1 採点フローの結合テストを実施する
  - 未採点一覧からの採点画面遷移 -> チェック操作 -> スコアプレビュー -> 下書き保存 -> 復元 -> 採点確定の一連のフローが動作することを確認する
  - 採点確定後にスキルレポートが正しく表示されることを確認する
  - Manager・受講生それぞれの視点でスキルレポートの表示内容が適切に制御されていることを確認する
  - 排他制御の警告（楽観的ロック）が正しく表示されることを確認する
  - _Requirements: 1.1, 2.7, 2.8, 4.3, 4.5, 6.1, 6.2, 8.1_

- [x]* 8.2 (P) 受入基準に基づくテストカバレッジを追加する
  - `saveDraft` Server Action のテスト: 新規下書き保存、既存下書きの上書き、復元確認を検証する
  - `finalizeGrading` Server Action のテスト: 正常確定、全項目未評価での拒否、`graded` 済み submission への拒否を検証する
  - フィードバックコメントのバリデーションテスト: 文字数チェック（0, 1, 2000, 2001 文字）を検証する
  - スキルレポートのクエリテスト: `category_large` 別集計の正確性、複数 submission がある場合の最新選択ロジックを検証する
  - _Requirements: 3.1, 3.2, 3.3, 4.1, 4.4, 5.5, 6.1, 6.4, 8.5, 13.1, 13.2_
